# Contributing

1. Większą pracę zaczynaj od Issue.
2. Pracuj na osobnym branchu.
3. Otwórz Pull Request z opisem zmiany, powodem i sposobem weryfikacji.
4. Nie commituj sekretów, tokenów ani prawdziwych danych uczestników.
5. Zmiana zakresu MVP wymaga aktualizacji `docs/requirements.md`.
6. Istotna decyzja techniczna powinna mieć ADR.
7. Ważniejsze zmiany powinny przejść co najmniej jedno review przed merge.
